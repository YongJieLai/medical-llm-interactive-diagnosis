# 外部方法移植 baseline 实验结果（空起步重跑·终版）

> 目标：把 MedClarify / MEDIQ / UoT 三个零训练方法原封不动移植到 AgentClinic-MedQA
> 开放式诊断场景，看它们的 failure case，以及是否达到它们声称的"关键证据覆盖"。

## ⚠️ 0. 重要更正（本版作废上一版的全部结论）

上一版（`external-baselines-results.md` 旧内容）存在一个**移植时的信息不对称 bug**：

- 外部方法的 doctor 起步时被喂了 `case_input.task`，而 `task` 含完整 OSCE（Objective + History +
  **Physical Exam + Test Results**），等于**开卷考试**；
- 上游方法（roleplay/react/sc/refine，与上游 EID-Benchmark 逐字一致）是**空起步**，连主诉都要第一轮自己问。

后果：外部方法"信息白送、无需提问"，于是出现"MEDIQ 84% turns=0、MedClarify 78% turns=0、覆盖率≈0"的
假象，被误归因为"自评置信度门控失效"。**这个归因是错的。**

本版修复：三个外部方法统一改为**空起步**（第一轮硬编码问主诉，病史/检查只能靠后续提问采集），
与上游交互场景完全对齐，5 个模式各 200 例重跑。以下所有数字均为空起步后的公平结果。

## 0.5 方法归属（本仓库内所有方法，四类，边界清晰）

> 此前文档把 roleplay 写成"我们基线"、把 refine_cv 写成"我们的方法"，造成"49–58.5% 都是我们的方法"的误解。现纠正如下：

| 类别 | 方法 | 准确率 | 归属 |
|------|------|:---:|------|
| **A. 上游论文原样方法（别人的，对照基线）** | cot / roleplay / react / sc / refine | 49.0–59.0%（cot 85.5% 为静态上界） | 逐字 fork 自上游 EID-Benchmark，`git diff` 为空 |
| **B. 上游方法 + 我们的插件** | refine_cv 系列（refine_cv / refine_cv_qwen / 各消融）、roleplay_cv、react_cv、react_cv2 | 45.0–58.5% | 上游各底座 + **我们的 CEV-GR 四检查门控**（详见 §7 底座移植性） |
| **C. 外部论文方法移植（别人的，零训练 baseline）** | MedClarify / MEDIQ / UoT | 26.0–44.0% | 从各论文移植，非我们的方法 |
| **D. 我们真正的原创** | **CEV-GR 插件本身** | — | Cross-model Evidence Verification + Gap-driven Refutation（四检查：claim / gap / refutation / decisive），非 standalone 方法，只能加载在某个底座上 |

**关键澄清**：
- 我们**没有一个"从零写起的独立方法"**。我们的原创贡献是**插件 CEV-GR**，它加载在"上游 refine 骨架"上即 refine_cv 系列。
- "49–58.5%" 区间里，**只有 57.5–58.5% 的 refine_cv 系列才是"带我们插件"的方法**；49%（roleplay）/ 53%（react）/ 59%（sc）/ 55%（refine）全是上游论文原样方法。
- **sc 底座 == refine_cv 的底座**（两者医生用同一个 `get_sc_doctor_system_prompt`），因此"sc + CEV-GR" = refine_cv，本表不再单列。
- **CEV-GR 底座敏感**：装到"采集-诊断解耦"底座上有效（roleplay 49→57.5%、refine 55→58.5%、sc 59→58.5 持平）；装到 ReAct（采集-诊断耦合 + `[DIAGNOSIS]`=终点）底座上反而掉 6.5–8pp（react 53→46.5/45）。详见 `docs/cev-gr-host-portability.md`。

## 1. 结论速览（公平对比）

| 方法 | 门控机制 | 空起步准确率 | 关键证据覆盖率（正确/错误） | 错题根因 |
|------|----------|:---:|:---:|:---:|
| **cot（静态全信息上界）** | — | 85.5% | — | — |
| **roleplay（上游基线）** | 交互 | **49.0%** | 60.6% / 49.6% | 70.6% 决策错 |
| **react** | 交互 | 53.0% | 52.5% / 34.4% | 67.0% 采集不足 |
| **sc** | 采集+总结 | 59.0% | — | 69.5% 决策错 |
| **refine（论文）** | 交互+门控 | 55.0% | 62.3% / 47.8% | 66.7% 决策错 |
| **refine_cv 系列（上游 refine + CEV-GR 插件）** | 交互+四检查门控 | 57.5–58.5% | 58.8–62.0% / 45.1–49.8% | 51–77% 决策错 |
| **roleplay_cv（roleplay + CEV-GR 插件）** | 交互+四检查门控 | **57.5%（+8.5pp）** | 34.6% / 31.1%（综合覆盖） | — |
| **react_cv（react + CEV-GR 通用移植）** | 交互+四检查门控 | 46.5%（−6.5pp） | 26.6% / 22.7% | give_up 0→13.2% |
| **react_cv2（react + CEV-GR 专用移植）** | 交互+method-agnostic 门控 | 45.0%（−8.0pp） | 25.6% / 22.7% | 诊断被 gate 带偏 |
| **MedClarify（DEIG）** | 自评 top1≥0.97 | 28.0% | 15.1% / 12.3% | **91.7% 采集不足** |
| **MEDIQ（abstention）** | 自评 Scale≥4 | 44.0% | 21.7% / 19.3% | **73.2% 采集不足** |
| **UoT（信息增益）** | 熵平分 H(x) | 26.0% | 17.8% / 14.7% | **87.2% 采集不足** |
| MEDIQ 强制问4轮（对照） | 同上+min_turns | 44.7% | 21.6% / 19.8% | 70.0% 采集不足 |
| MedClarify 强制问4轮（对照） | 同上+min_turns | 31.2% | 16.0% / 12.6% | — |

**四个核心结论（均为公平条件，可复现）**：

1. **三个外部方法没有一个达到它们声称的"关键证据覆盖"**：关键证据覆盖率仅 12–22%，而带我们
   CEV-GR 插件的方法（refine_cv 系列）52–62%。差 3–4 倍。

2. **它们的覆盖率不区分对错**：正确组 vs 错误组覆盖率差仅 +1.8~3.2pp（带插件方法 +9~18pp 全正向显著）。
   即它们采到的是"区分性噪声"，不是"确诊关键证据"。UoT 的熵平分、MedClarify 的 DEIG、MEDIQ 的
   abstention 选问题，在开放式诊断里都没导向确诊证据。

3. **准确率倒挂**：UoT（26%）、MedClarify（28%）甚至低于上游 roleplay（49%）、带我们插件的 refine_cv（58%），
   远低于 cot 静态上界（85.5%）。MEDIQ 44% 也低于带我们插件的方法（refine_cv 58%）。上一版"外部方法准确率高"纯属开卷假象。

4. **错题根因结构根本不同**（最锋利的一条）：带我们插件的 refine_cv 系列错题 51–77% 是"决策错"（证据采够了、输在
   决策）；三个外部方法错题 73–92% 是"采集不足"（连确诊证据都没采到，走不到决策环节）。

## 3. failure case 根因归类（错题里"采集不足" vs "决策错"占比）

| 方法 | 错题数 | 放弃诊断 | 采集不足 | 决策错 |
|------|:---:|:---:|:---:|:---:|
| roleplay（上游基线） | 102 | 1.0% | 28.4% | **70.6%** |
| react | 94 | 0% | 67.0% | 33.0% |
| sc | 82 | 0% | 30.5% | 69.5% |
| refine（论文） | 90 | 4.4% | 28.9% | 66.7% |
| refine_cv 系列（上游 refine + CEV-GR 插件） | 80–85 | 1–12% | 19–31% | **51–77%** |
| **MedClarify** | 144 | 0% | **91.7%** | 8.3% |
| **MEDIQ** | 112 | 0.9% | **73.2%** | 25.9% |
| **UoT** | 148 | 0.7% | **87.2%** | 12.2% |
| MEDIQ 强制问4轮 | 110 | 0.9% | 70.0% | 29.1% |

**这是整条研究线最干净的一条对比**：带我们插件的方法已经"跨过采集关"（错题主要在决策），三个外部方法
"死在采集关"（连确诊证据都没采到）。这正是 CEV-GR 的支点——把"关键证据采集"显式化、用客观覆盖度门控，
才能把外部方法没跨过去的那道关真正跨过去。

## 4. turns 分布（空起步后行为恢复正常）

| 方法 | 平均 turns | 分布特征 |
|------|:---:|:---:|
| UoT | 6.0 | 1–16 轮分布，正常交互 |
| MEDIQ | 8.1 | 1–16 轮分布，正常问诊 |
| MEDIQ 强制问4轮 | 9.0 | 强制 4 轮后继续问到 9 轮 |
| MedClarify | 3.9 | **94%（188/200）在 4 轮停** |
| MedClarify 强制问4轮 | 6.0 | 84%（168/199）在 6 轮停 |

**修正上一版结论**：上一版"MEDIQ 84% turns=0、MedClarify 78% turns=0 → 门控从不提问"是开卷假象。
空起步后 MEDIQ/UoT 都正常问诊。**但 MedClarify 的 DEIG 门控仍"过早停止"**（4 轮就 top1≥0.97 自信），
且它停在 4 轮时关键证据覆盖率只有 15%——这说明"模型自评置信度门控"的固有缺陷仍在（只是从 turns=0
退化为 turns=4），它把"已经问过几轮"误当成"证据已足够"。

## 5. 对 CEV-GR 的三点反向约束（本实验的直接产出）

1. **门控不能用模型自评置信度**：MEDIQ（Scale≥4）、MedClarify（top1≥0.97）都是自评门控，qwen-plus
   上要么过早停止（MedClarify 4 轮即停、覆盖率仅 15%）。门控必须靠**客观的关键证据覆盖度**，而不是
   模型自己觉得"够不够"。

2. **选问题不能用"信息增益 / 熵平分"**：UoT 的 H(x) 熵平分把候选集对半切，采到的是区分性噪声
   （覆盖率 17.8%、准确率 26%），不是确诊关键证据。选问题必须**由关键证据缺口驱动**（哪个关键事实
   还没采到就优先问哪个）。

3. **候选集必须覆盖 truth**：UoT 有相当比例 open-set 初始化就没把 truth 放进候选（上一版测到约 25%），
   候选不含 truth 则后续全白采。CEV-GR 需要在关键证据缺口识别阶段显式校验候选覆盖。

## 7. CEV-GR 移植到其它底座的结果（2026-11-26 补充，终版）

把 CEV-GR 四检查门控从 SC/refine 底座移植到其它底座，看插件是否底座无关。完整分析见
`docs/cev-gr-host-portability.md`。

> 先厘清：**sc 底座 == refine_cv 的底座**（两者医生用同一个 `get_sc_doctor_system_prompt`），
> 因此 "sc + CEV-GR" = refine_cv，不重复测。真正的新底座是 **react（ReAct）** 和 **roleplay**。

| 底座 | 上游原样 | +通用 CEV-GR | +react 专用 CEV-GR | Δ（最佳插件 vs 原样） |
|------|:---:|:---:|:---:|:---:|
| sc | 59.0% | refine_cv 58.5% | — | −0.5pp |
| refine | 55.0% | refine_cv 58.5% | — | +3.5pp |
| **roleplay** | 49.0% | **roleplay_cv 57.5%** | — | **+8.5pp** |
| **react（ReAct）** | 53.0% | react_cv 46.5% | **react_cv2 45.0%** | **−8.0pp** |

**结论：CEV-GR 是底座敏感的，不是万能插件。**

1. **roleplay 底座大胜（+8.5pp）**：roleplay 与 sc/refine 同构——医生是采集器、诊断交给独立
   diagnostician（"采集-诊断解耦"）。通用 CEV-GR 直接有效，且 roleplay 原样诊断器最弱（49%），
   四检查补短板空间最大。
2. **ReAct 底座结构性不兼容（−6.5～−8pp）**：通用移植（react_cv 46.5%）与专用移植（react_cv2
   45.0%）都掉点。根因不是"格式不匹配"，而是三个结构冲突——① `[DIAGNOSIS]` 是"不可逆终点"，
   被打回后行为退化；② 效率优先导致浅采集（8.5 turns，覆盖率 25%，比 roleplay/sc/refine 的
   33–35% 低一大截）；③ 采集-诊断单 agent 耦合，gate 干扰诊断连带破坏采集。
   - react_cv 的掉点是"诊断决策被破坏"：give_up 从 react 的 0% 涨到 13.2%（独立 diagnostician
     在浅 summary 上放弃），覆盖率反而略升（26.6% vs 25.3%）。
   - react_cv2 保留了 ReAct 医生自己的诊断、消除了 give_up（0%），但 gate 让医生"反复横跳"，
     最终诊断偏离一次到位的判断，准确率仍 45.0%。

**对 CEV-GR 定位的最终修正**：CEV-GR 是**"采集-诊断解耦"底座（sc/refine/roleplay 系）的可插拔
审计层**，不是全范式通用插件。论文里不要把它表述为"万能插件"。
