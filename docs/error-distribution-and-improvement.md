# 错误分布分析与提升空间（sc vs refine_cv）

> 数据来源：medqa 200 例 / 16 turns / qwen-plus，空起步。
> 判分：`deterministic_judge`（规则层 + DeepSeek 兜底）。错误类型：DeepSeek 逐例根因标注（165 例错题全量）。

## 0. 结论速览（30 秒）

1. **sc 与 refine_cv 的错误分布高度相似**：最大的错误类型都是"离题（off_system）+ 同系统错实体（wrong_entity）"，合计约 70%，其次是"过度诊断"（14–16%），"放弃诊断"很少（1–6%）。
2. **二者唯一实质差异不在错误类型，而在"证据利用效率"**：
   - refine_cv 的准确率随覆盖率**单调上升**（38% → 55% → 67% → 87%）；
   - sc 的准确率与覆盖率**无关**（恒定 58%）。
3. **提升空间的主战场在采集层**：约 70% 的错题（离题 + 错实体）对应低覆盖率（28–32%），是"提问方向没对准关键证据"所致；refine_cv 已证明"证据采够 → 准确率 87%"，但当前只有 7.5% 的 case 能采够 50% 覆盖。
4. **次要战场是诊断器去偏置**：过度诊断占 14–16%，但其覆盖率不低（32–33%），不是采集不足，而是诊断器"把常见病升级成严重病"的系统性偏置——**这一点 sc 与 refine_cv 几乎相同，说明它不是 CEV-GR 引入的**（修正此前"CV 诊断器过度诊断副作用"的小样本结论）。

---

## 1. 错误类型分布（全量逐例标注）

| 错误类型 | 含义 | sc（82 错） | refine_cv（83 错） |
|------|------|:---:|:---:|
| **off_system** | 诊断到完全不同的器官系统/方向 | **33（40%）** | **29（35%）** |
| **wrong_entity_same_system** | 同一系统内诊断错疾病实体 | **27（33%）** | **29（35%）** |
| **overdiagnosis** | 常见/良性/功能性 → 升级为严重/罕见/器质性 | 13（16%） | 12（14%） |
| **underdiagnosis** | 具体病 → 降级为宽泛大类 | 5（6%） | 6（7%） |
| **give_up** | 放弃诊断（insufficient data 等） | 1（1%） | 5（6%） |
| **judge_false_negative** | 实质正确、判分器误杀 | 3（4%） | 2（2%） |

**解读**：

- **离题 + 错实体合计 70–73%**，是绝对大头。这两类都属于"证据采偏/采不够"——医生问的问题没对准确诊所需的关键证据。
- **过度诊断 14–16% 且两方法几乎相同**（sc 16% > refine_cv 14%）。这**推翻**了上一轮"CV 诊断器有过度诊断副作用"的 16 例小样本结论：过度诊断是两种诊断器**共同**的偏置，不是 CEV-GR 的证据纪律引入的。
- **give_up 极少**（sc 1 例、refine_cv 5 例），说明"证据不足就放弃"不是主要失败模式。
- **judge_false_negative 极少**（2–4%），判分器基本可靠，不构成结论噪声。

---

## 2. 错误类型 × 覆盖率交叉（关键证据）

| 错误类型 | sc 覆盖率均值 | refine_cv 覆盖率均值 | 归因 |
|------|:---:|:---:|------|
| give_up | 10.0% | 15.2% | 采集严重不足 → 放弃 |
| off_system | 30.3% | 30.9% | **采集方向偏**（低覆盖） |
| wrong_entity | 32.1% | 28.2% | **采集不够区分**（低覆盖） |
| overdiagnosis | 33.3% | 32.0% | **覆盖率不低** → 诊断器偏置 |
| underdiagnosis | 31.5% | 39.4% | 混合 |
| judge_false_negative | 35.9% | 27.3% | 实质对 |

**这条交叉把"采集层问题"和"诊断层问题"干净地切开了**：

- 离题 + 错实体（约 70% 错题）的覆盖率都压在 28–32%，是**采集不足**的直接后果；
- 过度诊断（14–16%）的覆盖率有 32–33%（不算低），说明证据采到了一些，是**诊断器倾向把常见病升级**的偏置，与采集无关。

---

## 3. 覆盖率分层 → 准确率（本次最锋利的发现）

| 覆盖率区间 | sc 准确率 | refine_cv 准确率 |
|------|:---:|:---:|
| [0, 20%) | 58% | **38%** |
| [20%, 35%) | 58% | **55%** |
| [35%, 50%) | 61% | **67%** |
| [50%, 100%) | 58% | **87%** |

| | 正确组覆盖率 | 错误组覆盖率 | 差值 |
|------|:---:|:---:|:---:|
| sc | 33.1% | 31.4% | +1.7pp（几乎无区分） |
| refine_cv | 34.3% | 29.7% | +4.6pp |

**两条完全相反的曲线揭示了本质差异**：

- **sc**：准确率与覆盖率**无关**（恒定 58%）。它的 diagnostician 是"自由推理"，采多采少都一样——因为它不把证据当作约束，靠直觉/常识直接猜，证据覆盖率高也救不了它，低也拖不垮它。
- **refine_cv**：准确率随覆盖率**单调上升**（38% → 87%）。CEV-GR 的"证据纪律 + 验证门控"把诊断真正**锚定在采集到的证据上**——证据越充分，诊断越准，最高档 87%。

**这意味着 refine_cv 已经把"证据 → 诊断"这条链路打通了**，它的天花板纯粹是"证据采不够"：只有 **15/200（7.5%）** 的 case 覆盖率 ≥ 50%。而 sc 的问题是相反的——它根本没把证据用起来，覆盖率对它无效。

---

## 4. 提升空间（按杠杆排序）

### 层 1：采集层 —— 最大杠杆（治 70% 的错题）

**现状**：doctor 的 prompt 是"效率优先"（few turns + atomic inquiries），导致提问方向容易跑偏（40% 离题）或采不到区分性证据（33% 错实体），覆盖率中位仅 30%。

**方向**：把"关键证据缺口"作为提问的唯一驱动力，而不是"想到什么问什么"。

具体可做的三点（按可落地性排序）：

1. **区分性缺口驱动提问**：CEV-GR 的 gap check 目前是从"总结里缺什么"推的（被动），应改成"我当前 top-2 假设是什么、哪个检查能最干净地区分它们"（主动）。这本质是 MedClarify/MEDIQ 的"信息增益"思想，但要**用关键证据（诊断价值）而非熵**来打分——此前已证明熵平分采到的是"区分性噪声"（外部方法关键覆盖仅 12–22%）。
2. **覆盖率实时反馈**：把"还差哪些关键证据"作为显式线索喂回 doctor，让它带着缺口去问，而不是靠 turn limit 硬停。预期把覆盖率中位从 30% 抬到 45%+。
3. **主诉后先做"鉴别诊断短列表"**：首轮问完主诉后，先让 doctor 输出 top-3 假设 + 各自的确诊证据清单，后续提问严格围绕这份清单补齐。这直接抑制 off_system（问偏方向）。

**预期收益**：覆盖率中位 30% → 45–50%，按 refine_cv 的单调曲线，对应准确率从 58.5% 抬到约 **70–80%**（这是当前最大的、且已被数据支撑的空间）。

### 层 2：诊断层去偏置 —— 次要杠杆（治 14–16% 的过度诊断）

**现状**：过度诊断占 14–16%，覆盖率不低（32–33%），是诊断器"常见病优先升级成严重病"的偏置。

**方向**（低成本，可立即试）：
- 在 diagnostician 的 prompt 里加一条**"先验：优先考虑常见/功能性/自限性诊断，除非有明确的器质性阳性证据"**（Occam's razor / base-rate prior）。
- 或在 [GAPS] 阶段强制问一句："在现有证据下，是否存在一个**更常见、更简单**的诊断能解释全部症状？若有，请优先考虑它。"

**预期收益**：若把 14–16% 的过度诊断压掉一半，约 +7–8 例，对应 +3.5–4pp。

### 层 3：sc 的教训 —— 不要回到"自由推理"

sc 在低覆盖段（<20%）反而比 refine_cv 高（58% vs 38%），这看起来诱人，但**不可规模化**：它的 58% 是"与证据无关的恒定猜中率"，一旦要提升就得靠采集，而它又没有"证据→诊断"的转化机制。所以**不能为了低覆盖段的短期准确率放弃证据纪律**；正确做法是保留 refine_cv 的证据锚定，同时用层 1 把覆盖率提上去，让它的高覆盖段优势（87%）覆盖更多 case。

---

## 5. 下一步实验建议（按优先级）

1. **[P0] 区分性缺口驱动提问**：给 refine_cv 的 doctor 加"top-2 假设 + 区分性检查"机制，跑 200 例，主指标看**覆盖率中位**（预期 30% → 45%+），次指标准确率。这是唯一有数据直接支撑、且杠杆最大的改动。
2. **[P1] 诊断器 base-rate prior**：一条 prompt 的事，跑 200 例看过度诊断是否下降。
3. **[P2] 覆盖率实时反馈**：把关键证据缺口喂回 doctor，与 P0 可叠加。

**一句话总纲**：refine_cv 已经证明"证据够 → 87% 准确"，现在的瓶颈 100% 在"证据采不够"（70% 的错题是离题+错实体、覆盖率仅 28–32%）。所以下一步的战场是**把采集从"效率优先"改成"关键证据缺口优先"**，而不是继续调诊断器。
