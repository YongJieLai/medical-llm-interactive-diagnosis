# 主战场作战方案：从「区分假设」到「覆盖关键证据」

> 状态：**分析完成，方案 A 已验证为正结果**（2026-11-27）
> 前置：`error-distribution-and-improvement.md`（主战场=采集层）、`p0p1-improvement-results.md`（P0/P1 负结果）、`two-stage-explore-exploit-results.md`（两阶段负结果）。
> 结果：`cover-collection-results.md`（方案 A 覆盖率中位 31%→50%、准确率 +6.5pp）。
> 本文回答：主战场（采集层）到底该怎么打——即"关键证据缺口优先"如何从一句口号落成可执行、可证伪的方法。

## 0. 一句话结论

**主战场的打法不是"更聪明地选问题"，而是"更系统地覆盖关键证据"。**
把采集的锚点从**"区分当前假设对"（discriminate）**换成**"覆盖证据类别缺口"（cover）**——
这是对 P0、两阶段、乃至现有 gap check 三连负结果的直接修正。

## 1. 主战场为什么在这里（证据链回顾）

1. **refine_cv 已打通"证据→诊断"**：准确率随整体覆盖率单调上升 `38%→55%→67%→87%`，最高档 87%。
2. **瓶颈 100% 在采集**：只有 **7.5%（15/200）** 的 case 覆盖率 ≥ 50%，中位仅 30%。
3. **70% 错题（离题 35–40% + 错实体 33–35%）的覆盖率压在 28–32%**，是"提问方向没对准关键证据"。

所以：**只要把覆盖率中位从 30% 抬到 45–50%，按单调曲线外推准确率从 58.5% 抬到约 70–80%**，这是全项目最大的、且已被数据直接支撑的空间。

## 2. 为什么此前的尝试都失败（共同根因）

| 尝试 | 锚点 | 结果 | 死法 |
|---|---|---|---|
| P0（top-2 区分提问） | 当前 top-2 假设 | −4.5pp，覆盖率 34.3%→31.0% | 假设错→区分错方向→漏掉纠正性证据 |
| 两阶段（推迟主动选择 K=4/6/8） | 仍锚 top-2 假设 | −3~−4pp | 推迟只是把同一失败挪后，假设到 K 轮仍错 |
| 现有 gap check（诊断后补采） | "区分当前诊断 vs 替代" | 被动后置，触发太晚 | 先 FINISH 才发现缺什么，且还是 discriminate 导向 |
| 外部三方法（MedClarify/MEDIQ/UoT） | 信息增益（熵） | 26–44% | 熵采到的是"区分性噪声"，关键覆盖仅 12–22% |

**共同根因：锚点都落在"假设"（hypothesis）上，而不是"证据"（evidence）上。**

- "区分 top-2" → 在错误假设空间内找差异 → 漏掉能推翻方向的关键证据。
- "熵/信息增益" → 最大化两个候选间的信息差 → 采的是"区分性噪声"，不是"确诊性证据"。
- 关键证据覆盖率分析早已给出反证：正确组 vs 错误组**关键证据覆盖差 +9~18pp（全显著），而整体覆盖只差 +2~5pp**——决定对错的是"关键证据采没采到"，不是"采得多不多、区分得干净不干净"。

## 3. 方案设计：锚点转换

**核心转变**：

```
旧：doctor 想到什么问什么（效率优先、atomic 单点）   →  覆盖率中位 30%
旧：gap check 诊断后补"区分当前诊断的缺失信息"        →  被动、后置、discriminate
新：采集期就维护一张"关键证据缺口清单"，定向覆盖       →  主动、前置、cover
```

关键区分（一句话说清 P0 与主战场的差别）：

> **P0 问的是"哪个检查能区分我的 top-2 假设"（假设驱动）；主战场要问的是"哪些证据类别还没覆盖到、哪条能确立/推翻诊断"（证据驱动）。** 前者在假设错时锁死，后者天然保持开放、覆盖方向。

## 4. 三层方案（按杠杆与风险排序）

### 方案 A：去「效率优先」→「广覆盖证据框架」（最小改动，立即可测）

**改什么**：doctor 的 system prompt 第 1 条从
> "Efficiency: Gather sufficient information in **as few turns as possible**."

改成
> "Comprehensiveness: systematically cover a **complete evidence framework** before finishing."

并注入一个 8 维结构化问诊框架（主诉 / 现病史起病与病程 / 伴随症状 / 既往史 / 用药与过敏史 / 社会与职业暴露史 / 针对性查体 / 最相关的实验室与影像），作为"关键证据类别"的候选空间。

**为什么是最大杠杆**：`as few turns as possible` 是覆盖率中位 30% 的**直接元凶**——它在采集期就鼓励"少问、窄问、快结束"。去掉它 = 直接松绑覆盖率。

**成本**：纯 prompt、零额外 LLM 调用、零训练、不泄题。

### 方案 B：证据类别缺口驱动的采集规划（核心，前移 gap check）

**改什么**：把 gap check 从"诊断后"前移到"采集期"。每 N 轮（或每轮），用一个采集规划器（复用 DeepSeek，或新增轻量角色）根据当前对话输出：

```json
{"evidence_gaps": [
  {"category": "occupational_exposure", "question": "是否长期接触矽尘/石棉？", "diagnostic_value": "high"}
]}
```

doctor 从清单里定向采集**未覆盖的证据类别**。

**与 P0 的本质区别**：清单项是**"证据类别缺口"**（职业暴露史、影像学、特异性实验室…），不是**"区分两个假设的检查"**。即使当前假设全错，清单仍然指向"还可能缺什么关键证据"。

**关键风险（必须防）**：规划器自由生成清单，可能又退化成"想到什么问什么"。**缓解**：用方案 A 的 8 维框架约束清单的候选空间（category 只能从框架里选），让"覆盖"有结构、可审计。

### 方案 C：覆盖感知终止（天花板最高，风险最高）

**改什么**：把 FINISH 条件从"我觉得问够了"改成"关键证据覆盖率达标才 FINISH"。

**风险**：运行时没有 oracle 的"关键证据"标注（`key_facts.json` 是知道 ground_truth 后的回溯标注）。需要先造一个**运行时"关键证据缺口"的代理信号**——这正是方案 B 的输出；方案 B 成功，方案 C 才可接。

## 5. 预期收益与验证口径

| 指标 | 现在 | 目标 | 依据 |
|---|---|---|---|
| 覆盖率中位 | 30% | 45–50% | 方案 A/B 直接抬采集量 |
| 覆盖率 ≥50% 的 case 占比 | 7.5% | 30%+ | 同上 |
| 准确率 | 58.5% | 70–80%（外推） | refine_cv 单调曲线 |

**主指标必须是覆盖率**（唯一强信号），准确率作辅——这是贯穿全项目的经验（准确率分辨不出方法好坏，覆盖率能）。

**证伪标准**（提前写死，避免又跑出一个"我们没想清楚就下结论"的实验）：
- 方案 A 若覆盖率中位无提升 → "效率优先"不是瓶颈，回到重新诊断采集失败根因。
- 方案 B 若覆盖率升但准确率不升 → 说明采到的仍是"区分性噪声"，需要回到"关键 vs 噪音"的证据价值定义上。
- 方案 B 若覆盖率升、准确率升 → 主战场打通，接方案 C + 写论文。

## 6. 下一步实验（按顺序）

1. **[已完成] 方案 A**：`RefineCVCoverScenario`（广覆盖版 doctor），200 例 / 16 turns。**正结果**：覆盖率中位 31%→50%（+19pp）、≥50% case 7.5%→51.5%、准确率 +6.5pp（McNemar p=0.124）。详见 `cover-collection-results.md`。
2. **[下一步] 方案 B**：在方案 A 基础上加"证据类别缺口"采集规划器（前移 gap check），对照 A vs A+B，主看覆盖率中位与"错误组覆盖率"（当前仍 43.4% vs 正确组 53.7%）。
3. **层 2 去偏置**：在 A+B 底座叠加 base-rate prior，治 overdiagnosis 14–16%。
4. **方案 C**：仅在 A+B 验证"覆盖→准确"因果后启动。
