# 面板补全实验（负结果）：消除环境瓶颈后准确率纹丝不动

## 实验

上一轮过程归因发现：方案A 里医生的检查请求 **72.6% 落空**（reporter 返回 Not specified），
并判断"主战场是 benchmark 环境瓶颈"。为验证，做对照实验：

1. 把 200 例检查面板全部补全（`data/exam_panels` 61→200，`gen_exam_panel.py`：
   qwen-plus 生成 + deepseek 审核，199/200 PASS，1 例 FAIL 手动修复），
   exam_facts 从 **14.87 条/例 → 39.5 条/例**（补全 2.7 倍）。
2. 用补全数据 `agentclinic_medqa_panel.jsonl` 重跑方案A（`refine_cv_cover_panel`，200 例 / 16 turns）。

## 结果

| 指标 | 稀疏面板(原始) | 补全面板 | 变化 |
|---|---|---|---|
| **准确率** | 64.5% | 64.5% | **+0.0pp** |
| 检查命中率 | 27.4% | 48.5% | +21.1pp |
| 每例采到检查 | 7.6 条 | 14.3 条 | +88% |
| 关键检查采到 | 569/931 | 555/931 | **-14 条** |
| **关键检查覆盖率** | 61.1% | 59.6% | **-1.5pp** |
| 医生 query/test | 8.6 / 6.2 | 8.2 / 5.8 | 基本不变 |

## 关键发现：补全面板让医生"查得到更多"，但多查的全是噪音

- 补全面板确实缓解了环境瓶颈：命中率 +21.1pp，采到检查量翻倍（7.6→14.3 条/例）。
- **但多采到的几乎全是「非关键检查」**（常规生命体征/实验室/排除性检查），关键检查
  不仅没多采，反而少采了 14 条（569→555）。
- 医生下检查的次数没变（~6 次/例），补全面板只是让每次请求"批量返回更多常规结果"。
- **结果：准确率 64.5% 纹丝不动。**

## 结论（两个认识修正）

### 修正 1：环境瓶颈不是主因

上一轮「61.9% 未采到是 env_unavailable → 主战场是环境瓶颈」的判断被本实验证伪：
消除环境瓶颈（命中率 +21pp）后，准确率 **0 变化**。env_unavailable 在统计上占比高，
但不是诊断失败的**因果瓶颈**。

### 修正 2：主战场是「关键检查的定向采集」

完整证据链：

| 实验 | 准确率 | 含义 |
|---|---|---|
| oracle_full（喂完整证据） | 87.5% | 诊断器绝对上限 |
| oracle_key（喂关键证据） | 80.0% | 「采够关键证据」可达 |
| oracle_exam（只喂检查） | 70.5% | 检查结果本身的价值 |
| 方案A 交互采集（稀疏） | 64.5% | 关键检查覆盖率 61.1% |
| 方案A 交互采集（补全） | 64.5% | 关键检查覆盖率 59.6% |

- 交互采集（64.5%）距 oracle_key（80%）差 **15.5pp**，这是「采集损失」。
- 这个损失**不是「环境不给检查」**（补全面板证明），而是**「医生没采到关键检查」**
  （关键检查覆盖率仅 61%，且补全面板没有改善它）。
- 补全面板是**错误方向**：它增加「可查的噪音检查」，反而稀释了关键检查的采集。

## 下一步方向

问题重新聚焦回：**如何在不泄露的前提下，把关键检查覆盖率从 61% 提到 ~80%**。
方案A（8 维证据框架）已经做了第一步（42.3%→61.1%），剩余 39% 的关键检查需要更强的
「症状→判别性检查」引导——但「注入检查清单」会泄露（之前已否决），这是下一步要攻的难点。
