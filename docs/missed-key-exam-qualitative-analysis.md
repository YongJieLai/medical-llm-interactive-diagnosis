# 未采到关键检查的定性分析：知识缺口(B) vs 信息上界(C)

## 问题

上一轮行为分析发现：方案A（refine_cv_cover，广覆盖）的关键检查覆盖率已提到 61.1%，
但仍有 **38.9% 的关键检查没采到**；而 oracle 实验证明「采够关键证据」可达 80%。
这 38.9% 的 gap 根因有两种候选：

| 假设 | 含义 | 验证方式 |
|---|---|---|
| B. 知识缺口 | qwen-plus 医生不知道「这症状该查哪个检查」 | 没采到的检查里，多为「常规该想到却漏了」 |
| C. 信息上界 | 罕见特异性检查模型根本想不到 | 没采到的检查里，多为「罕见/高度专科」 |

本分析把「没采到的关键检查」逐条列出来做定性分类，判定 B 还是 C 占主导。

## 方法

1. **清单提取（规则，无 LLM）**：复用 `analyze_key_facts` 的采集判定口径
   （reporter 返回的检查结果中出现的 fact 编号 = 已采到），从 `key_facts.json`
   的 `key_exam` 里挑出方案A未采到的条目，共 **362 条**，涉及 141/200 例。
2. **LLM 定性分类**：每条给 DeepSeek「主诉 + 正确诊断 + 该检查结果」，标注两个轴：
   - `role`：confirmatory（判别性，指向确诊）/ routine（常规基线/生命体征）/ negative（阴性排除）/ uncertain
   - `retrievability`（仅 confirmatory）：standard（教科书标准路径该想到）/ specialized（高度特异/罕见）

## 结果

### 1. 未采到的 362 条里，三成是「标注噪音」

| role | 条数 | 占比 | 含义 |
|---|---|---|---|
| confirmatory（判别性） | 244 | 67.4% | 真正该采却没采的确诊性检查 |
| routine（常规基线） | 59 | 16.3% | 生命体征/一般筛查，key_facts 误标为关键 |
| negative（阴性排除） | 56 | 15.5% | 正常/阴性结果，价值在排除而非确诊 |
| uncertain | 3 | 0.8% | — |

**附带修正**：`key_facts.json` 的 `key_exam` 把 31.8% 的常规基线/阴性排除项也标成了
「关键检查」，稀释了覆盖率。真正的「判别性检查未采到」是 244 条，而非 362 条。

### 2. 判别性检查里，91.8% 是「常规该想到却漏了」

| retrievability | 条数 | 占比 |
|---|---|---|
| standard（标准路径该想到） | 224 | **91.8%** |
| specialized（罕见想不到） | 20 | 8.2% |

样本（standard）：EMG 重复刺激（MG）、AChR 抗体（MG）、淋巴结活检 CD20（DLBCL）、
MRI 脑白质病变（PML）、淋球菌筛查（DGI）、右膝关节压痛/跟腱压痛（反应性关节炎）、
胸腹水体征（Meigs）、STI 筛查阳性（DGI）……

### 3. 漏采与对错的关系（弱相关，但错误略重）

| | 漏采 ≥1 条 standard 判别检查的 case 占比 |
|---|---|
| 错误 case（60 例） | 46 / 60 = **77%** |
| 正确 case（81 例） | 57 / 81 = **70%** |

漏采 standard 判别检查在两组都普遍，但错误组略高，说明它是可补救的贡献因素之一
（非唯一决定因素）。

## 结论

**假设 B（知识缺口）占绝对主导，假设 C（信息上界）只占 8.2%。**

- 真正没采到的判别性检查 244 条里，**224 条（91.8%）是「教科书标准临床路径上该想到
  却漏了」的检查**，只有 20 条（8.2%）是「罕见特异性检查想不到」。
- 因此 38.9% 的 gap **不是 prompt 天花板**，而是采集端的知识缺口——医生（qwen-plus）
  在「主诉 → 该查哪些标准检查」这一步存在系统性缺失。

**主战场明确了：不是换模型、不是接受天花板，而是给采集器注入「症状 → 标准检查」的
临床路径知识。**

## 下一步方向（候选）

1. **临床路径知识注入（针对 B）**：把 MedQA 每个疾病的「确诊标准检查」整理成
   「症状/主诉 → 标准检查清单」的路径库，在采集阶段作为外部知识喂给医生
   （注意：只给「疾病无关的标准检查路径」，不给病例专属清单，避免泄露）。
2. **细化归因**：对 224 条 standard 检查回看 trace，区分「医生下了别的检查（方向错）」
   还是「医生根本没下检查（漏了）」，进一步定位是「检索不到」还是「优先级排错」。
