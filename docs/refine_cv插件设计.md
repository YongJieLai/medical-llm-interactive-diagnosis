# CEV-GR 插件设计：跨模型证据核对 + 缺口驱动反证

> 场景名 `refine_cv`。在 refine（30 例 73.3% 的最强基线）之上加一个**零训练、纯 prompt + 确定性规则**的插件，
> 目标是对治 30 例失效里的大头：**锚定锁死(37%) + 正确假设被丢弃(24%) + 关键信息未采集(14%)**，以及小头的读反/编造(6%)。

---

## 一、设计依据（为什么这么做，不是拍脑袋）

前两代插件的失败已经把"不能怎么做"讲清楚了，本设计的三条原则都是从失败里长出来的：

| 已否定的做法 | 失败原因（30 例实证） | 本设计的对策 |
|------------|---------------------|-------------|
| HPR：加 DDx 列表角色，诊断器从列表选 | 诊断器**照抄列表第 1 名**，列表生成有强随机性 → 66.7%，回归 4 例 | **保留诊断器自由推理**，不引入列表决策者 |
| refine_eg：三条证据纪律写进**同一个模型**的 prompt | 同一模型"生成+核对"同源偏差，verifier 用"clinical misstatement"自我合理化 → 60.0% | **跨模型解耦**：qwen 生成，DeepSeek 核对 |
| 原 refine verifier：只判"信息是否充分" | 只查"够不够"，不查"证据真假"、不查"缺哪条" | verifier 升级为**双查**：幻觉核对 + 信息缺口标注 |

**一句话设计原则：生成与核对解耦（跨模型）、把"只查幻觉"升级为"查幻觉 + 查信息缺口"、反证用确定性触发而非自由发挥。**

---

## 二、方法总览

在原 refine 链 `summarizer → diagnostician → verifier` 上改造，**不新增决策者角色**，只升级两个环节：

```
doctor(千问)  ──多轮提问──▶  patient(千问)
      ▲                           │
      │ 定向追问                   ▼
      │                    summarizer(千问)  → 结构化 summary
      │                           │
      │  ┌────────────────────────▼────────────────────────┐
      │  │  diagnostician(千问) 自由推理                      │
      │  │  · 每条支持证据必须回指 summary 原句（MedCite 零训练版）│
      │  │  · 显式列出"要确诊还缺的关键信息"（缺口意识）         │
      │  └───────────────────────────────────────────────────┘
      │                           │ 诊断 + 证据 + 缺口
      │  ┌────────────────────────▼────────────────────────┐
      │  │  verifier(DeepSeek，跨模型，确定性规则)            │
      │  │  ① 幻觉核对：证据声明 vs summary → [矛盾/未出现]   │
      │  │  ② 缺口标注：诊断 vs 主要鉴别 → 缺失关键信息        │
      │  │  ③ 反证触发：诊断 N 轮不变 → 强制列 1 反证 + 1 备择  │
      │  └───────────────────────────────────────────────────┘
      │                           │ 规则决策（非 LLM 自由发挥）
      └───────────────────────────┘
```

轮次预算 10 轮内：缺口/反证 → 转成**具体的下一个 [QUERY]/[TEST]**，回喂给 doctor。

---

## 三、三个核心机制

### 机制 1：跨模型证据核对（对治 6% 读反/编造 + 兜底）

- **做什么**：diagnostician 出诊断后，DeepSeek verifier **不看诊断推理过程**，只拿「诊断的证据声明清单」和「summary 原文」逐条比对，输出每条的判定。
- **判定标签**（确定性，非自由文本）：
  - `[SUPPORTED]` 证据声明能在 summary 中找到对应原句；
  - `[CONTRADICTED]` 声明与 summary 相反（如"无法屈曲"被写成"无法伸直"）；
  - `[HALLUCINATED]` 声明不在 summary 里（如编造"tcdB PCR negative"，而 summary 里是 Not specified）；
  - `[UNDETERMINED]` summary 里该项是 pending/Not specified，模型却当成确定结论用。
- **为什么换模型**：同源偏差已实证——同一个 qwen 生成又核对，会流畅地自我合理化。DeepSeek 与 qwen 独立，且 DeepSeek 是我们手头最强的核对模型。

### 机制 2：信息缺口标注（对治 14% 未采集 + 支撑反证）

- **做什么**：DeepSeek verifier 同时输出「为区分当前诊断与主要鉴别诊断，**summary 里尚缺失**的关键信息」，按区分度排序（top 2–3）。
- **这是"渐进采信息"适配的关键**：CoVe/MedCite 只核对"已在场的事实"，发现不了"该问没问的"。缺口标注把 verifier 从"查幻觉"升级为"查信息缺口"。
- **示例**（对应 medqa_2 巨结肠四方法全错）：若当前诊断是 colic，缺口标注应输出"出生后胎便排出时间 / 是否慢性便秘"——正是锁定巨结肠的鉴别性信息。

### 机制 3：确定性反证触发（对治 37% 锚定 + 24% 正确假设被丢弃）

- **做什么**：**确定性规则**判断——若当前诊断连续 **≥2 轮不变**（锚定信号），强制 verifier 输出「当前诊断最强的 1 条反证 + 1 个未被排除的鉴别诊断」。
- **为什么确定性触发，而非让 LLM 自由发挥**：弱模型自由发挥会自我合理化（HPR verifier 已踩坑）。规则触发保证"锚定必复盘"，不依赖模型自觉。
- **对治"正确假设被丢弃"**：反证复盘会把被丢弃的假设重新拉回视野（medqa_4 首轮有 AIN、后被嗜酸粒细胞带偏到 EGPA——反证触发会逼它解释"AIN 被排除的证据是什么"）。

## 四、确定性决策规则（verifier 输出后，不用 LLM 决策）

```text
输入：幻觉核对结果 H、缺口标注 G、反证触发 F、当前轮次 t、预算 T
输出：下一轮动作（PASS / 定向追问）

1. 若 H 中存在 [CONTRADICTED] 或 [HALLUCINATED] 或 [UNDETERMINED]：
      → 判定"证据不可信"，打回 diagnostician 重诊（不采新信息，先纠错）
2. 若 H 全部 [SUPPORTED] 且 G 非空 且 t < T：
      → 把 G 中区分度最高的 1 条，转成 doctor 的下一轮定向 [QUERY]/[TEST]
3. 若 F 触发（诊断 ≥2 轮不变）且 t < T：
      → 把"反证对应的那 1 个待验证点"转成 doctor 下一轮提问
      （优先于规则 2，先破锚定再补缺口）
4. 若 H 全部 [SUPPORTED] 且 G 为空 且 F 未触发：
      → PASS，接受当前诊断
```

**关键点**：决策是**规则树**，不是"让 verifier 自己判断 PASS/INCOMPLETE"（原 refine 的 INCOMPLETE 判定就因此不稳定）。

## 五、评估方案

- **样本**：30 例（id 0–29），复用已有 evidence 标注 + 确定性 judge 管线。
- **主指标**：确定性 judge 重判后的准确率，对比 refine 的 **73.3%**。
- **失效拆解指标**（按既有 failure_metrics 管线）：
  - 锚定 / 正确假设被丢弃 / 未采集 / 读反 各修复了几例、回归了几例；
  - 幻觉核对是否抓到 [HALLUCINATED]/[UNDETERMINED]（对治 medqa_16 型）；
  - 缺口标注是否命中"锁定诊断的鉴别性证据"（对治 medqa_2 型）；
  - 反证触发次数 vs 诊断实际变化次数（验证"锚定必复盘"是否生效）。
- **对比基线**：refine 73.3%、refine_hpr 66.7%、refine_eg 60.0%。

## 六、预期失效风险（诚实标注，不吹）

| 风险 | 表现 | 对策 |
|------|------|------|
| DeepSeek verifier 自身噪声 | 误判 [SUPPORTED]/[HALLUCINATED] | 规则化输出标签 + 只信"明确矛盾/明确缺失"，模糊归 [UNDETERMINED] 而非强行判定 |
| 缺口标注过度索取 | 10 轮内问不完，永远 PASS 不了 | 缺口按区分度排序，每轮只取 top-1，且规则 4 允许 G 剩余时轮次用尽即 PASS |
| 跨模型调用成本 | token 翻倍（每轮多一次 DeepSeek 核对） | 仅在接受诊断前核对（每例 1–3 次），非每轮核对 |
| 换模型引入风格差异 | DeepSeek 判据与 qwen 输出格式不齐 | verifier 只吃"结构化证据清单"，不吃自由文本诊断 |

## 八、与文献的对应关系（证明不是闭门造车）

| 本设计组件 | 文献来源 | 做了哪些适配 |
|-----------|---------|-------------|
| 证据回指 summary 原句 | MedCite（语句级引用） | 去掉外部检索，回指对象改成"对话 summary" |
| 跨模型独立核对 | CoVe（独立验证步骤） | "独立"落到**换模型**，而非同一模型重读 |
| 信息缺口标注 | MedKGI 信息增益 / ontology 找区分症状 | 去掉 KG/熵计算，用 DeepSeek 直接列"缺失的鉴别性信息" |
| 确定性反证触发 | MedKGI"候选不变→找反证"、argumentation"反驳备择" | 做成**规则触发**，避免弱模型自由发挥 |

---

## 结论

本设计**不是照搬任何一篇文献，而是抽取"核对解耦"共识，并针对我们任务的三个特殊性**（渐进采信息、弱模型、零训练）做了三处改造：跨模型、查缺口、确定性反证。是否有效，以 30 例确定性 judge 的实测为准，不以冒烟测试为准（前两代都栽在"冒烟有效、批量失效"上）。
